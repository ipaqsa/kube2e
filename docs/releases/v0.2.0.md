# kube2e v0.2.0

Release date: 2026-09-18

This release tightens the **case contract**: cases are now described by a published
JSON Schema that editors and CI can both check, the run owns the namespace instead
of each case, and `logs` with `match: none` became a real absence assertion rather
than a check that passed after one poll tick.

**This release contains breaking changes.** See
[Breaking changes](#-breaking-changes) before upgrading — existing case files
carrying `namespace:` will no longer parse.

## Highlights

- 📐 **Case JSON Schema** (`schemas/case.schema.json`, draft 2020-12) describing the
  full case contract, with editor completion via a `yaml-language-server` modeline.
- ✅ **`kube2e tests validate`** — gate suites in CI against the schema without
  touching a cluster.
- 🎯 **Namespace moved to the run** — `--namespace` / `KUBE2E_NAMESPACE`, replacing
  the per-case `namespace:` field.
- 🔒 **`--force-conflicts`** to take ownership of fields held by another Server-Side
  Apply field manager.
- 🔍 **Publish digest is observable** — logged on success and optionally written to
  a file, so a pipeline can pin `run --remote` to the exact image it published.
- 🐛 **`logs match: none` fixed** — absence is now proven by the whole window
  elapsing, not by a single tick.

## Features

### Case JSON Schema

`schemas/case.schema.json` (draft 2020-12) describes the full case contract, with
reusable `$defs` formats for Kubernetes durations, resource names, namespaces, and
OCI references. Example cases and the scaffolded starter case carry a modeline, so
editors validate and complete them as you type:

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/ipaqsa/kube2e/main/schemas/case.schema.json
version: v1
```

Examples point at the in-repo path; the scaffold points at the published URL.

### `kube2e tests validate`

```bash
kube2e tests validate ./examples          # every suite under a parent directory
kube2e tests validate ./examples/nginx    # a single suite
```

`<dir>` is either a suite directory (one containing `cases/`) or a parent whose
immediate children are suites — the same discovery `run` and `tests publish`
already use. Every `cases/*.yaml` file is reported as `ok` or `FAIL` with a JSON
pointer to each offending value, and the command exits non-zero when any file is
invalid:

```
$ kube2e tests validate ./broken
broken
  ok   cases/ok.yaml
  FAIL cases/rollout.yaml
       /steps/0/logs/match: value must be one of 'any', 'all', 'none'
  FAIL cases/scale.yaml
       /steps/0/wait/timeout: 'tomorrow' does not match pattern '^(?:0|[-+]?(?:(?:[0-9]+(?:\\.[0-9]*)?|\\.[0-9]+)(?:ns|us|µs|μs|ms|s|m|h))+)$'

3 case files checked, 2 invalid
Error: 2 of 3 case files are invalid
# exit status 1
```

The schema is **stricter than the case parser**: the parser accepts any string
where a duration or an enum belongs, so a malformed `timeout` or an unknown `match`
policy previously surfaced only mid-run, after earlier steps had already applied
resources to a live namespace.

It does **not** replace `run --dry-run`, which additionally renders templates and
resolves the `objects` map. The schema is embedded in the binary, so validation
never depends on the schema's `$id` being reachable over the network.

### Namespace is a run flag

The run owns the namespace via `--namespace` / `KUBE2E_NAMESPACE` (default
`default`). It is created when absent, **never deleted**, and inherited by
namespaced objects that do not set one explicitly.

```bash
kube2e run ./examples --namespace kube2e
```

### `--force-conflicts`

Server-Side Apply ownership conflicts still fail by default. The new flag
(`KUBE2E_FORCE_CONFLICTS`) sets `ForceOwnership` so kube2e can acquire fields owned
by another field manager:

```bash
kube2e run ./examples --force-conflicts
```

### Observable publish digest

`tests publish` logs the digest of the pushed image on success and, with
`--digest-file` / `KUBE2E_TESTS_PUBLISH_DIGEST_FILE`, writes the bare `sha256:...`
line to a file. A remote run records the digest it resolved in `remote.digest` of
the `--report-file` report, so a pipeline can pin the exact image it published:

```bash
kube2e tests publish ./examples \
  --remote ghcr.io/example/kube2e-tests:v0.2.0 \
  --digest-file digest.txt

kube2e run . --remote "ghcr.io/example/kube2e-tests@$(cat digest.txt)" \
  --kubeconfig ~/.kube/config
```

The digest file is written with mode `0o600` (parent directory `0o750`) and
overwrites an existing file without asking.

### Report additions

The run report now records `namespace`, `forceConflicts`, and `remote.digest`
alongside the existing fields.

## Fixes

### `logs` with `match: none` is now a real absence assertion

`none` passed as soon as a single poll tick found nothing, so a step could succeed
before the string it forbids had any chance to be logged — absence was effectively
reported after roughly one `interval` of output. It now watches for the whole
`timeout` and fails the moment the string appears in any pod, returning a new
`ErrLogsContainForbidden` sentinel.

| | Before | After |
|---|--------|-------|
| Passing | First poll tick with no match — roughly one `interval` | Only after the full `timeout` window elapses with no match |
| Failing | Never failed on appearance; timed out with `ErrLogsNotContain` if the string was present at every tick | Fails as soon as the string appears, with `ErrLogsContainForbidden` |
| `timeout` meaning | Deadline | **Observation window** — the step always runs its full duration |

### `logs` with `match: all` no longer passes on partial evidence

A pod whose logs could not be read was dropped from the comparison entirely, so
`all` could pass on the strength of one readable pod while the others were never
checked. Unreadable pods now count as resolved but never as matched, keeping the
check pending instead of passing on partial evidence.

No change for targets whose pods are all readable.

## ⚠️ Breaking changes

### `namespace:` is no longer a case field

Parsing is strict, so a case that still carries `namespace:` now **fails to parse**
rather than having the field ignored:

```
parse case file 'cases/old.yaml': unmarshal case file: error unmarshaling JSON:
while decoding JSON: json: unknown field "namespace"
```

**Migration:** delete the `namespace:` line from each case and pass
`--namespace <ns>` to `kube2e run`. A run that previously relied on per-case
namespaces to isolate suites from each other needs one invocation per namespace.

### `match: none` steps now take their full `timeout`

Existing cases using `match: none` keep working, but each such step now runs for its
whole `timeout` instead of returning almost immediately. The `2m` default is far too
long for an observation window — keep it short (`examples/pod/cases/silent.yaml`
uses `10s`).

A case that was passing only because the forbidden string had not been logged *yet*
will now correctly fail.

### Go 1.27.1 required to build from source

Prebuilt binaries and the container image are unaffected.

## Requirements

The README gains a **Requirements** section documenting the cluster floors:

| Actions used | Minimum cluster version |
| --- | --- |
| Any suite containing `exec` | **v1.30** |
| Everything else (`ensure`, `patch`, `wait`, `assert`, `logs`, `delete`) | **v1.22** |

`exec` streams over WebSockets using the `v5.channel.k8s.io` subprotocol only, with
no SPDY fallback — that subprotocol is on by default from v1.30. On an older cluster
every other action still works; only `exec` fails.

## Dependencies

- Kubernetes libraries v0.36.1 → **v0.37.0**
- controller-runtime v0.24.1 → **v0.25.1**
- go-containerregistry v0.21.6 → **v0.22.1**
- testify v1.11.1 → **v1.12.1**
- `go` directive 1.26.0 → **1.27.1**; builder image `golang:1.26` → **`golang:1.27`**
- `golang.org/x/text` moves from indirect to direct

Per the upstream version skew policy the v1.37 clients are supported against
v1.36–v1.38 API servers; older clusters back to the floors above are expected to
work, since kube2e only uses long-stable APIs. No API usage changed with the bump.

## Install

### Binaries

Download from the release assets and verify the checksum:

- `kube2e-linux-amd64`
- `kube2e-linux-arm64`
- `kube2e-darwin-arm64`

```bash
sha256sum -c kube2e-linux-amd64.sha256
```

### Container image

```bash
docker pull ghcr.io/ipaqsa/kube2e:0.2.0
```
